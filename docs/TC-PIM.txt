  CATATAN TEKNIS: SECURITY: FILE UPLOAD VALIDATION (CROSS-CUTTING, 8 TC)
  Dikonfirmasi via Playwright discovery run langsung terhadap OrangeHRM OS 5.9
================================================================================

  LATAR BELAKANG: setelah 148 TC fungsional selesai, user secara eksplisit
  meminta eksplorasi security untuk file upload (exe/apk disguised sebagai
  gambar). Diuji di 4 titik upload berbeda: foto profil Add Employee, foto
  profil Personal Details, Attachments di Contact Details, dan Data Import.

  [BUG NYATA DIKONFIRMASI] Upload foto profil di Add Employee HANYA
    memvalidasi EKSTENSI nama file, BUKAN konten/magic bytes file itu
    sendiri. File executable (header PE "MZ...") atau Android APK (header
    ZIP "PK..") yang di-rename jadi .jpg LOLOS validasi tanpa error apa
    pun, dan berhasil tersimpan via POST /api/v2/pim/employees (status
    200, dikonfirmasi live dengan 2 jenis file berbeda: TC-PIM-ADD-28,
    TC-PIM-ADD-29). Baseline pembanding (TC-PIM-ADD-31): file .exe dengan
    ekstensi ASLI (tanpa rename) memang DITOLAK dengan pesan "File type
    not allowed", jadi validasinya ADA tapi bisa di-bypass dengan rename
    ekstensi sederhana, bukan sama sekali tidak tervalidasi.

  [TEMUAN POSITIF] Trik double-extension ("photo.jpg.exe", ekstensi
    TERAKHIR tetap .exe) TIDAK bisa bypass validasi (TC-PIM-ADD-30):
    validator ternyata cek ekstensi TERAKHIR yang sebenarnya, bukan
    tertipu substring ".jpg" di tengah nama file.

  [TEMUAN POSITIF, BUG TIDAK MELUAS] 3 titik upload lain yang diuji
    TERNYATA TIDAK kena bug yang sama:
      - Attachments di Contact Details (TC-PIM-CONTACT-09): exe ditolak
        dengan benar, "File type not allowed".
      - Data Import (TC-PIM-DATAIMPORT-05): exe-renamed-.csv ditolak
        server dengan response 400, bukan diproses.
      - Baseline Data Import exe murni (TC-PIM-DATAIMPORT-06): ditolak
        dengan benar.
