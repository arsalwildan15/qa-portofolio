  URL        : /web/index.php/auth/login
  Framework  : Vue 3 + OXD Design System (oxd-* components)

  LOCATORS (CONFIRMED):
    Username input       : page.getByPlaceholder('Username')
    Password input        : page.getByPlaceholder('Password')
    Login button           : page.getByRole('button', { name: 'Login' })
    Error message (login)  : page.locator('.oxd-alert--error')
    Required validation    : page.locator('.oxd-input-field-error-message')
    "Forgot password?"     : page.locator('.orangehrm-login-forgot-header')
                              [TEMUAN] Elemen ini adalah <p> dengan trailing
                              space di textContent, BUKAN <a> — tidak punya
                              accessible role "link". getByRole('link', ...)
                              tidak akan menemukannya.
    Dashboard heading      : page.getByRole('heading', { name: 'Dashboard' })
    User dropdown           : page.locator('.oxd-userdropdown-tab')
    Logout menu item        : page.getByRole('menuitem', { name: 'Logout' })
                              [TEMUAN] Logout dirender sebagai menuitem di
                              dropdown, bukan sebagai <a role="link">.

  API ENDPOINT (CONFIRMED):
    POST /web/index.php/auth/validate
    - Kredensial valid atau invalid → selalu 302 (redirect server-side)
    - Tidak ada 401/403 — pola session PHP klasik
    - Username 255/256 karakter tidak memicu 5xx (TC-LOGIN-17/18)
    - Username tidak punya atribut maxlength di client — browser menerima
      input berapa pun panjangnya (TC-LOGIN-18)
    - Leading/trailing spaces pada username TIDAK di-trim oleh client —
      dikirim apa adanya ke server dan login gagal (TC-LOGIN-28, dibuktikan
      via inspeksi request payload)
    - Whitespace-only input (hanya spasi) DI-trim oleh client menjadi
      kosong, diblokir validasi "Required" sebelum sempat submit
      (TC-LOGIN-15/16)

  [TEMUAN PENTING] USERNAME TIDAK CASE-SENSITIVE
    Asumsi awal (dari pengalaman app lain) adalah username case-sensitive.
    Verifikasi langsung terhadap instance ini (OrangeHRM OS 5.9) membuktikan
    SEBALIKNYA: "admin" (huruf kecil semua) berhasil login dengan akun
    "Admin". TC-LOGIN-13 awalnya ditulis mengasumsikan case-sensitive dan
    GAGAL saat dijalankan — bukan karena bug script, tapi karena asumsi
    yang salah. Test ditulis ulang untuk mendokumentasikan perilaku AKTUAL.
    Password TETAP case-sensitive (dibuktikan terpisah di TC-LOGIN-14).

================================================================================
  TEMUAN SELAMA EKSPLORASI (bukan bug, tapi worth dicatat)
================================================================================

  1. Username TIDAK case-sensitive, password TETAP case-sensitive.
     (TC-LOGIN-13 vs TC-LOGIN-14)

  2. Input username TIDAK punya attribute maxlength — tidak ada batas
     panjang di sisi client sama sekali. (TC-LOGIN-18)

  3. Leading/trailing spaces pada username TIDAK di-trim sebelum dikirim
     ke server, sedangkan whitespace-only DI-trim jadi kosong oleh
     validator "Required" di client. Dua perilaku berbeda untuk dua
     kasus yang mirip. (TC-LOGIN-15/16 vs TC-LOGIN-28)

  4. "Forgot your password?" dirender sebagai <p> dengan click handler,
     bukan <a> — tidak API-accessible lewat role "link".

  5. "Logout" dirender sebagai menuitem di dropdown, bukan <a role="link">.

  6. Tidak ditemukan rate limiting / lockout setelah 5x percobaan login
     gagal berturut-turut pada demo publik ini. (TC-LOGIN-37)

     untuk demo publik ini (dikonfirmasi tidak menyebabkan error/hang).
