================================================================================
  FUNGSI & IMPACT MODUL, PERFORMANCE
================================================================================

  Performance adalah modul penilaian kinerja karyawan. Alurnya berlapis:
    1. Configure > KPIs: HR mendefinisikan KPI (Key Performance Indicator)
       per JOB TITLE, lengkap dgn rentang rating Min/Max dan opsi "Make
       Default Scale".
    2. Manage Reviews: Admin/HR membuat review utk seorang employee
       (Employee Name, Supervisor Reviewer, Review Period, Due Date), lalu
       meng-Activate-nya. KPI yg muncul di form evaluasi = PERSIS set KPI
       milik Job Title employee tsb.
    3. Evaluate: reviewer mengisi rating per KPI + komentar + Review
       Finalization (Date of Completion, Final Rating, Final Comments),
       Save lalu Complete -> review jadi read-only permanen.
    4. Configure > Trackers: jurnal/catatan kinerja per employee dgn
       reviewer tertentu (BUKAN konfigurasi KPI/review, lihat Catatan
       Teknis).

  IMPACT kalau ada gap di sini: data Performance adalah dasar keputusan
  karier (kenaikan gaji, promosi, bonus, PIP). Rating yg tersimpan salah
  (mis. nilai non-angka diam-diam jadi 0, lihat TC-PERF-EVAL-15/BG-373)
  langsung merusak Final Rating seorang karyawan TANPA ada error yg
  terlihat oleh reviewer. Kebocoran akses (ESS membaca review orang lain)
  membuka data penilaian yg sifatnya rahasia. Karena review yg sudah
  Completed tidak bisa di-undo, kesalahan data di tahap evaluasi bersifat
  permanen.

  PERILAKU PENTING, SIKLUS STATUS REVIEW:
    [TEMUAN] Inactive -> (Activate) Activated -> (Save evaluasi) In Progress
    -> (Complete + Ok) Completed. Detail:
      - Save di form Add Review TIDAK pindah halaman: form direset + toast.
        Status awal selalu "Inactive"; selfReviewStatus adalah field terpisah.
      - Setelah Activated, ikon baris berganti Edit -> Evaluate.
      - Save di halaman evaluasi = DUA request: PUT evaluation/supervisor +
        PUT evaluation/final (complete:false) -> status "In Progress".
      - Complete membuka dialog "Confirm Review Submission" (menyatakan
        review jadi read-only & "cannot be undone"); Ok mengirim
        complete:true -> "Completed". PUT evaluasi berikutnya ditolak 403.
      - Review Inactive yg di-evaluasi langsung via API: PUT supervisor 422,
        PUT final 403 (server menegakkan aturan, bukan cuma UI).

  PERILAKU PENTING, PRASYARAT MEMBUAT & MENG-ACTIVATE REVIEW:
    [TEMUAN] (1) "Supervisor Reviewer" HANYA menawarkan supervisor yg sudah
    ter-link ke employee via PIM > Report-to. Employee tanpa supervisor ->
    "No Records Found" utk SEMUA pencarian, Save diblokir client-side
    ("Invalid"). (2) Activate ditolak API dgn 400 "Cannot activate review
    for employees who doesn't have a Job Title with KPI" kalau Job Title
    employee kosong / tidak punya KPI. Create review sendiri TIDAK
    mensyaratkan Job Title. Kedua prasyarat ini dibungkus util
    `setupReviewableEmployee()` (employee baru + akun login di-link sbg
    supervisor Direct + Job Title opsional) dan `createReview()` (setup +
    create + Activate opsional, Job Title "QA Engineer" yg punya KPI).

  PERILAKU PENTING, KPI DEFAULT SCALE EKSKLUSIF SECARA DIAM-DIAM:
    [TEMUAN] Menandai KPI B "Make Default Scale" utk Job Title yg SAMA dgn
    KPI A (sudah default) DITERIMA 200, dan KPI A otomatis un-default tanpa
    pesan apa pun. Response save KPI A tetap bilang isDefault:true (snapshot
    saat itu), tapi daftar yg dibaca ulang hanya menunjukkan KPI B "Yes".

  PERILAKU PENTING, TRACKERS BUKAN KONFIGURASI KPI:
    [TEMUAN] "Configure > Trackers" dan "My/Employee Trackers" adalah fitur
    jurnal/catatan kinerja per employee, BUKAN konfigurasi KPI/review --
    koreksi atas asumsi audit lama.

  PERILAKU PENTING, FORMAT TANGGAL BERUBAH ANTAR SESI (LINGKUNGAN):
    [TEMUAN] Placeholder tanggal site-wide (dari Admin > Localization)
    berganti "yyyy-dd-mm" <-> "yyyy-mm-dd" antar sesi di demo publik (pola
    reset yg sama dgn korupsi identitas empNumber=7). Nilai yg DIKETIK
    ditafsirkan sesuai format yg sedang tampil: mengetik 2026-07-10 di
    bawah yyyy-dd-mm tersimpan sbg 7 Okt (terkirim 2026-10-07). Solusi:
    util `fillDate()` (src/utils/dateInput.ts) membaca placeholder dan
    menyusun ulang nilai ISO ke format tampil; locator tanggal wajib match
    KEDUA placeholder. Date of Completion di TC EVAL memakai tanggal
    hari==bulan (2026-07-07) supaya kebal terhadap pergantian format ini.

  KOREKSI PENTING, CONSOLE 404 DI TC ACTIVATE (bukan BG-356):
    Klaim awal batch 1 bahwa "BG-356 intermiten di semua TC yg memanggil
    Activate & makin sering seiring jumlah data" SALAH. Console 404 di TC-TC
    tsb berasal dari SETUP: set Job Title via halaman PIM > Job memicu
    GET /api/v2/admin/job-titles/<id>/specification -> 404 (Job Title tanpa
    file spek; ditangani app, tidak ada exception, BUKAN bug), tapi teks
    console error-nya identik dgn bug sungguhan sehingga mencemari console-
    error check. Setup kini set Job Title via API PUT
    /api/v2/pim/employees/<id>/job-details -> TC-TC Activate (REVIEW-04/05/
    06/08/11/12, semua EVAL) bersih. BG-356 yg asli HANYA direproduksi saat
    membuka ULANG halaman edit review yg sudah Activated (TC-PERF-REVIEW-10).
    Risiko yg sama mungkin ada di TC modul lain yg set Job Title via UI ->
    dijadwalkan dicek di Fase 4.
