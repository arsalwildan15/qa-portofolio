  FRAMEWORK: Vue 3 + OXD Design System, sama dengan PIM/Recruitment. Semua
  sub-screen Admin > Job dipakai lewat SPA client-side navigation; hard
  reload (page.goto langsung ke sub-route) pada beberapa sub-route (Job
  Titles, Pay Grades, Job Categories, Work Shifts, Corporate Branding)
  mengembalikan BODY KOSONG / shell blank, BUKAN 404 -- dikonfirmasi lewat
  beberapa percobaan direct-navigate yang konsisten gagal. Employment
  Status adalah satu-satunya sub-screen Job yang hard-reload-safe secara
  langsung. Page object di suite ini SELALU goto() ke list URL dari
  halaman yang sudah authenticated (bukan navigasi submenu manual), yang
  terbukti reliable di semua 7 sub-screen.

  URL & API ENDPOINT PER SUB-SCREEN (CONFIRMED):

    USERS
      List   : /web/index.php/admin/viewSystemUsers
      Add    : /web/index.php/admin/saveSystemUser
      API    : GET /api/v2/admin/users?limit=50&offset=0&sortField=
               u.userName&sortOrder=ASC
      Form fields (confirmed): Username, User Role (dropdown), Employee
      Name (autocomplete, getByPlaceholder('Type for hints...'), sama
      pola dengan Hiring Manager di Recruitment), Status ([TEMUAN

      diisi saat Status belum dipilih), Password, Confirm Password (2
      input type=password berurutan di DOM).

    JOB TITLES

      Add    : /web/index.php/admin/saveJobTitle
      API    : GET /api/v2/admin/job-titles?limit=50&offset=0&
               sortField=jt.jobTitleName&sortOrder=ASC
      Form fields (confirmed): Job Title (text), Job Description
      (textarea), "Job Specification" (file upload -- SATU-SATUNYA
      sub-screen Job dengan file input, high-value target upload-
      security sama pola dengan Resume Candidate), Note (textarea).

    PAY GRADES
      List    : /web/index.php/admin/viewPayGrades
      Add form: /web/index.php/admin/payGrade (SINGULAR, bukan plural
                seperti list URL -- dikonfirmasi beda dari dugaan awal)
      API     : GET /api/v2/admin/pay-grades?limit=50&offset=0
      Form fields (confirmed): Name (text) saja di form Add. Currencies
      per pay grade adalah sub-section TERPISAH yang hanya muncul
      setelah pay grade pertama disimpan (di luar scope TC pass ini).

    EMPLOYMENT STATUS

      Add    : /web/index.php/admin/saveEmploymentStatus
      API    : GET /api/v2/admin/employment-statuses?limit=50&offset=0
      Form fields (confirmed): Name (text) saja.

    JOB CATEGORIES
      List   : /web/index.php/admin/jobCategory
      Add    : /web/index.php/admin/saveJobCategory
      API    : GET /api/v2/admin/job-categories?limit=50&offset=0

    WORK SHIFTS
      List   : /web/index.php/admin/workShift
      Add    : /web/index.php/admin/saveWorkShifts

      Form fields (confirmed): Shift Name (text), From (time), To

      scope TC pass ini).

    CORPORATE BRANDING
      Form   : /web/index.php/admin/addTheme
      API    : GET /api/v2/admin/theme
      [TEMUAN PENTING] Form ini BUKAN form "Add" seperti sub-screen lain
      -- TIDAK ADA tombol "Save". Tombol yang ada: "Reset to Default",
      "Preview", "Publish". "Publish" yang berfungsi sebagai commit
      perubahan (confirmed dari label tombol, bukan diasumsikan sama
      dengan "Save").
      Field (confirmed): 6 color picker (Primary/Secondary Color,
      Primary/Secondary Font Color, Primary Gradient Color 1/2) + 3 file
      upload (Client Logo, Client Banner, Login Banner) -- 3 file input
      terkonfirmasi lewat input[type="file"] count = 3, SEMUANYA target
      upload-security, bukan cuma 1 seperti sub-screen lain.

      [SAFETY CONSTRAINT -- PENTING] "Publish" di form ini BUKAN create
      record baru (seperti Save di sub-screen lain), tapi MENGUBAH THEME
      GLOBAL yang dilihat SEMUA user demo publik ini secara bersamaan,
      mirip Configuration (Email/LDAP/dst). Klik Publish dengan payload
      upload-security (exe-renamed) kalau ternyata DITERIMA akan benar-
      benar mengganti logo/banner demo publik untuk semua orang, bukan
      cuma menambah 1 record uji seperti Job Title/Pay Grade. Karena itu
      TC-ADMIN-CORPBRAND-02/03/04/05 di suite ini SENGAJA TIDAK pernah
      klik "Publish" -- validasi hanya diuji sampai TITIK SETELAH file
      dipilih (cek pesan error client-side "File type not allowed" atau
      sejenisnya), TIDAK sampai commit. Ini DIBATASI SECARA SENGAJA demi
      keamanan demo bersama, konsisten dengan constraint yang sama untuk
      Configuration, BUKAN gap yang diabaikan diam-diam.

  SECURITY: UPLOAD VALIDATION (TC-ADMIN-JOBTITLE-07/08, TC-ADMIN-
  CORPBRAND-04/05, pola sama dengan TC-PIM-ADD-28/29 dan

  diharapkan ditolak. Hasil aktual tiap TC didokumentasikan apa adanya
  di STATUS masing-masing TC di bawah (lihat SUMMARY untuk rekap).

  KONSISTENSI DELETE ACTION: [TEMUAN PENTING] Semua sub-screen simple-list
  (Pay Grades, Employment Status, Job Categories, Job Titles, Work
  Shifts, Users) punya 2 ikon aksi per row dengan urutan trash (delete)
  LALU pencil (edit) -- BUKAN edit-lalu-delete seperti intuisi umum.
  Dikonfirmasi lewat inspeksi innerHTML row (bi-trash muncul sebelum
  bi-pencil-fill di DOM). Semua page object di suite ini pakai tombol
  AKSI PERTAMA (.oxd-table-cell-actions button pertama) sebagai Delete.

  [TEMUAN: SHARED-DEMO FLAKINESS DI BAWAH BEBAN PARALEL] Saat seluruh TC
  Admin dijalankan dengan Playwright default (fullyParallel, banyak worker)
  terhadap demo publik yang sedang dipakai sesi lain secara bersamaan,
  beberapa TC acak (goto() setelah Save, evaluate() setelah navigasi)
  kadang gagal karena server lambat atau context destroyed akibat
  navigasi SPA yang belum selesai. TC yang SAMA PERSIS lulus bersih saat
  dijalankan --workers=1 (serial). Pola ini konsisten dengan temuan
  flakiness shared-demo yang sudah didokumentasikan di sesi PIM/
  Recruitment sebelumnya -- bukan bug di test maupun aplikasi.

  UNIQUE DATA: Nama job title/pay grade/employment status/job category/
  work shift dan username dibuat via src/data/testData.ts (uniqueName,
  uniqueEmail yang sudah ada di suite ini, dipakai ulang bukan dibuat
  baru) supaya tidak kolisi dengan data seed demo maupun run sebelumnya
  terhadap backend demo publik yang sama.
