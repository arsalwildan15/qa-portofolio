  Information (pass ketiga, dispatch ini) sedang berjalan. Pass pertama
  (39 TC): User Management > Users, semua 5 sub-screen Admin > Job (Job
  Titles, Pay Grades, Employment Status, Job Categories, Work Shifts),
  plus Corporate Branding. Pass kedua (34 TC): semua 5 sub-screen Admin >
  Qualifications (Skills, Education, Licenses, Languages, Memberships)
  dan Admin > Nationalities. Pass ketiga / dispatch ini (Organization):
  General Information selesai (6 TC); Locations dan Structure masih

  Total TC saat ini: 79 (73 + 6 General Information).

  BELUM DICAKUP (scope eksplisit untuk pass berikutnya, BUKAN gap yang
  disengaja diabaikan tanpa dicatat):
    - Organization > Locations, Structure (sedang dikerjakan di dispatch
      yang sama dengan General Information, commit terpisah menyusul)
    - Configuration > Email Configuration, Email Subscriptions,
      Localization, Language Packages, Modules, Social Media
      Authentication, OAuth Client, LDAP Configuration
  Alasan: scope di atas butuh discovery + implementasi terpisah yang
  signifikan (terutama Configuration, yang punya safety constraint khusus
  karena berbagi infrastruktur demo publik -- lihat CATATAN TEKNIS di
  bawah).

  CATATAN CAKUPAN ORGANIZATION > GENERAL INFORMATION (live discovery,
  dispatch ini): screen ini TIDAK berbentuk form Add/Edit seperti semua
  sub-screen Admin lain -- ini SATU record organisasi tunggal yang selalu
  ada, ditampilkan read-only secara default, dengan switch "Edit" untuk
  mengaktifkan field. [TEMUAN PENTING] TIDAK ADA field upload logo di
  screen ini sama sekali (`input[type="file"]` count = 0, dikonfirmasi
  live baik di mode view maupun edit) -- asumsi awal di scoping bahwa
  ada field logo di sini TIDAK TERBUKTI; upload logo/banner tetap hanya
  ada di Corporate Branding (sudah dicakup pass pertama). Karena itu
  TIDAK ADA TC file-upload-security trio untuk screen ini -- coverage
  security dialihkan ke XSS + SQLi di field teks sebagai gantinya.

  CATATAN CAKUPAN QUALIFICATIONS + NATIONALITIES (live discovery,
  dispatch ini): kelima sub-screen Qualifications TIDAK 100% identik
  seperti yang diduga di scoping awal:
    - Skills PUNYA field kedua "Description" (textarea) -- SATU-SATUNYA
      sub-screen di grup ini dengan field tambahan, sehingga mendapat set
      TC paling lengkap (8 TC, termasuk SQLi khusus di Description dan
      IDOR dedicated).
    - Education PUNYA label field "Level", BUKAN "Name" seperti 4
      sub-screen lain -- dikonfirmasi live. AdminSimpleListPage diberi
      parameter fieldLabel (default "Name") untuk menangani ini.
    - Licenses, Languages, Memberships, dan Nationalities identik secara
      struktural di level form/API (1 field Name, 2 tombol aksi per row
      trash-lalu-pencil, API shape sama: GET/POST list collection, PUT
      .../{id}, DELETE bulk collection dengan body {ids: [...]}) --
      dikonfirmasi live lewat discovery run. Untuk 4 screen ini, TC
      boundary (300 char) dan security payload (XSS vs SQLi) DISEBAR
      berbeda per screen (bukan diduplikasi 4x identik) supaya tetap ada
      coverage representatif tanpa TC filler yang mekanismenya
      benar-benar sama, konsisten dengan pola yang sudah dipakai pass
      pertama untuk Pay Grades/Employment Status/Job Categories.
    - [TEMUAN PENTING] Nationalities TIDAK identik dengan Licenses/
      Languages/Memberships dalam SATU hal: datanya berisi ~196 record
      REAL (hampir semua negara di dunia, dikonfirmasi live lewat
      meta.total pada API), bukan cuma beberapa seperti 4 screen lain,
      dan list-nya TIDAK punya search/filter box maupun kontrol
      pagination yang kelihatan. Konsekuensinya: assertion "row baru
      muncul di list" via scan baris UI (pola yang dipakai di semua
      screen Admin lain di suite ini) TERBUKTI GAGAL live untuk
      Nationalities, karena row baru tidak selalu masuk 50 baris
      pertama yang di-render. TC-ADMIN-NATIONALITY-01 (Add) dan -06
      (Delete) karena itu diverifikasi via API langsung (GET/DELETE by
      id) bukan scan baris UI -- adaptasi yang disengaja dan didokumentasikan,
      bukan TC yang "dilemahkan" diam-diam.
