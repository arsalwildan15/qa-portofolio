================================================================================
  FUNGSI & IMPACT MODUL, LEAVE
================================================================================

  Leave adalah modul cuti OrangeHRM: Admin memberi jatah cuti (Entitlement)
  per employee per Leave Type per Leave Period, employee mengajukan cuti
  sendiri (Apply, status "Pending Approval"), Admin/supervisor menyetujui
  atau menolak (Approve -> "Scheduled", Reject -> "Rejected"), dan Admin
  juga bisa langsung membukukan cuti untuk employee (Assign Leave, langsung
  "Scheduled" tanpa approval). Employee bisa membatalkan request miliknya
  sendiri (Cancel -> "Cancelled").

  IMPACT kalau ada gap di sini menyentuh UANG & HAK KARYAWAN secara langsung:
  saldo cuti yang salah hitung (dobel potong, tidak dikembalikan saat
  reject/cancel, weekend ikut terpotong) berarti karyawan kehilangan hak
  cuti atau perusahaan membayar cuti yang tidak berhak. Gap kontrol akses
  (ESS bisa approve cuti sendiri, approve request yang sudah dibatalkan)
  adalah pelanggaran segregation of duties, bukan sekadar bug tampilan.

  PERILAKU PENTING (dikonfirmasi live):
    1. Tanpa entitlement, Apply Leave TIDAK bisa dipakai sama sekali
       (halaman menampilkan "No Leave Types with Leave Balance"), jadi
       hampir semua TC diawali createLeaveEntitlement().
    2. Saldo dipotong SAAT APPLY (status masih "Pending Approval"), bukan
       saat approval. Approve tidak memotong lagi; Reject dan Cancel
       mengembalikan saldo penuh.
    3. Rentang yang mencakup akhir pekan dipecah SERVER-SIDE jadi record
       per hari kalender; hari Sabtu/Minggu berstatus "Weekend" 0 jam dan
       tidak memotong saldo.
    4. Assign Leave oleh Admin langsung "Scheduled" (melewati approval).
       Kalau saldo tidak cukup, muncul dialog "Confirm Leave Assignment"
       yang menawarkan OVERRIDE -- Confirm tetap membuat record walau saldo
       0 (saldo bisa negatif). Dialog hanya muncul kalau baris entitlement
       untuk leave type tsb ADA (walau nilainya 0).
    5. Add Entitlement adalah UPSERT: Save memunculkan dialog konfirmasi
       "Updating Entitlement ... 0.00 will be updated to X" BAHKAN untuk
       employee yang belum punya entitlement sama sekali, dan dialog ini
       bisa telat > 2.6 detik di demo yang lambat. LeaveEntitlementPage.
       save() kini menunggu MANA DULUAN: dialog Confirm atau POST langsung.
       Setelah save sukses, app me-redirect dirinya sendiri via timer JS --
       page.goto() tepat di jendela itu kena net::ERR_ABORTED, jadi ada
       jeda tetap 2 detik (settleAfterSave) + retry 1x di goto() semua
       page object Leave.
    6. Pemilihan Leave Type memicu fetch saldo ASYNC -- panel "Leave
       Balance" yang dibaca terlalu cepat masih "0.00 Day(s)" (stale) dan
       menyebabkan 400 "No Working Days Selected". selectLeaveType()
       menunggu GET /api/v2/leave/employees selesai.
    7. [TEMUAN APLIKASI, gap UX] Untuk rentang MULTI-hari yang overlap
       atau melebihi saldo, client menjalankan pre-flight check sendiri
       lalu DIAM-DIAM tidak mengirim POST -- tanpa toast, tanpa dialog.
       Toast "Leave Balance Exceeded" hanya muncul untuk kasus 1 hari
       (ditolak server). Karena itu TC memakai hasOverlap() dan
       getRealTimeBalanceFor() untuk memilih tanggal yang aman.
    8. getRealTimeBalanceFor() dan hasOverlap() mengonversi tanggal ke ISO
       yyyy-mm-dd: endpoint API selalu ISO, berbeda dengan input UI.
       (Bug script lama: tanggal yyyy-dd-mm dikirim mentah -> 422 untuk
       hari > 12, atau diam-diam query tanggal yang tertukar.)
    9. Leave Period terdefinisi (leavePeriodDefined: true), periode saat ini
       2026-01-01 s/d 2027-01-30 -- relevan untuk boundary periode
       (TC-LEAVE-ASSIGN-06).

    dgn kedua placeholder) + fillDate(input, value, valueFormat) yang
    menyusun ulang nilai ke format tampil; LeaveListPage.rowByDate() mencari
    baris sesuai format tampil (BUKAN regex "dua-duanya", krn 2026-12-07 vs
    2026-07-12 adalah hari berbeda). Fix ini memulihkan 4 TC lama yang
    sempat rusak: ASSIGN-01, ASSIGN-02, LIST-01, LIST-03.
